# spec/

The Kamui ISA specification, written in Markdown. This folder is the architecture: implementations
(`kamui-llvm`, `kamui`) are checked against it, never the other way around.

## Files

| File | Content |
|---|---|
| [ptx-table.md](ptx-table.md) | The two-way table between PTX and Kamui. Generated by `tools/catalog/gen_table.py` from `tests/corpus/catalog.yaml`; the PTX side is filled, the Kamui side follows the extension specifications |

Planned: `base.md` (RV64 I, M, A, F, D, Zfh, Zba, Zbb, Zbs, Zicond and the SIMT register model) and one file per
`Xkm` extension, named after the extension in lower case (`xkmsimt.md`, `xkmwarp.md`, ...).

## Conventions

- Every instruction entry has: mnemonic, encoding, operands, semantics in prose and pseudo-code (the Sail model is
  normative when they disagree), the PTX construct that justifies it, and the NVVM intrinsic or LLVM IR construct
  behind that PTX construct.
- A pull request that adds an instruction edits the specification, the Sail model, the encodings,
  `ptx-table.md` and the conformance suite together.
- `ptx-table.md` is never edited by hand: change the catalog and run `python tools/catalog/gen_table.py`.
